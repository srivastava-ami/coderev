How the pipeline works

PR→fmt · validate · tflint · checkov · terraform test→plan posted on PR→site preview URL→merge to main→you approve 'production'→terraform apply→wrangler deploy→social drafts / opt-in posts

Nothing reaches production without your approval click. A plan that would delete a DNS record or the Pages project fails the build.

Free-tier limits that matter

  • Cloudflare free: Pages has a monthly build/deploy cap (direct uploads included), WAF gives the managed ruleset plus a small number of custom and rate-limit rules, Web Analytics is free and cookieless.
  • R2: 10 GB free. Terraform state is a few KB.
  • GitHub Actions: unlimited minutes and free environment approvals on public repos.
  • X: the free API tier can post, but the monthly cap is small. Fine for a blog cadence.
  • LinkedIn: the free "Share on LinkedIn" product can post to your profile. Tokens last 60 days, so the pipeline opens a reminder issue before expiry.
  • Instagram: free, but it needs a Business or Creator account linked to a Facebook Page, and every post needs an image. The build generates one per post.

Security design

  • One Cloudflare API token scoped to this zone and account, with an expiry. R2 keys are scoped to the state bucket only. Both live in GitHub secrets, never in files.
  • Third-party actions are pinned by commit SHA. Workflow permissions are read-only by default. Dependabot and gitleaks run on every PR.
  • Existing DNS records (including the genome and nx-viz subdomains) are imported, not recreated, so nothing drops during adoption.
  • The site is static, so it only accepts GET/HEAD; other methods are blocked at the edge.
