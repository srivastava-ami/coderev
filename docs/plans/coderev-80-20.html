Target pipeline

Everything outside the blue box is deterministic. The LLM can't move a finding, lower its severity or rename its rule. Its novel findings must quote an anchorable diff line, and they go to "Verify" unless evidence confirms them. CI fails when more than 20% of inline comments come from the LLM.

Key design decisions

  • New code lives in internal/pr/…. The existing coderev . scan is untouched. Legacy findings enter through finding.FromLegacy (C03).
  • The diff index is the single authority (C09/C10). The old parsePatchLines delegates to it (C11), which fixes the \ No newline off-by-one.
  • Rules are data in internal/config/prrules/*.toml and are embedded. There are five matcher kinds: regex, tsquery, hclpath, predicate and clone. Cross-file logic is a small named predicate registry, so new rules don't need Go unless they need a new predicate.
  • No new Go dependencies. HCL parsing uses the tree-sitter HCL grammar already in the go-tree-sitter module.
  • Every external call (git, gh, ocr, docker, the LLM) sits behind an interface with a fake, so each chunk's test runs offline.
  • The ocr session schema gets checked against the v1.14.2 source (internal/session/persist.go) before C47 is coded. The round-trip test is C63.

  • Open Code Review (ocr) is Alibaba's open-source review agent. It's Apache-2.0, comes from github.com/alibaba/open-code-review and its site is open-codereview.ai. Its other features are a 3-tier line-positioning and reflection module, effort levels (low/medium/high), many providers (Anthropic, OpenAI, Gemini, Qwen, DeepSeek and others), built-in rules for 40+ languages, saved sessions with an HTML viewer, and its own AACR-Bench benchmark.
  • coderev is your tool.
